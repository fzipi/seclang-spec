# AGENTS.md — working in seclang-spec

This repository holds the **SecLang specification**: the rule language implemented by
ModSecurity v2, libmodsecurity v3 and Coraza. It contains the normative text, the
Architecture Decision Records (ADRs) behind every choice where engines diverge,
engine-neutral conformance test data, a three-engine compatibility matrix, two reference
adapters that run the tests against real engines in CI, and a Hugo site that publishes it
all. Read this file before changing anything; the invariants below are enforced by
`tools/validate.py` and by CI.

## Layout

| Path | Contents | Edit how |
|---|---|---|
| `spec/00-conventions.md` … `spec/10-logging.md` | The specification, one chapter per topic (conventions, lexical, grammar, processing model, directives, variables, operators, transformations, actions, body processors, logging). Every feature is a `###` heading followed by a `**Status:** Core\|Extended\|Deprecated\|Engine-specific` line. | By hand. Changing a Core feature's semantics or its status needs an ADR (`spec/00-conventions.md`, "Spec versioning"). |
| `adr/` | ADRs `0001`…, `README.md` index table, `0000-template.md`. Categories: Divergence, Clarification, Deprecation, Extension. A Divergence ADR MUST have a `## Tests` section naming existing test files. | Copy the template; add a row to `adr/README.md` (the validator cross-checks number, category and status). |
| `tests/engine/**/*.yaml` | Engine-tier profiles (go-ftw-style YAML): `rules`, optional `files:`, `requires:` (Extended anchors), `tests[].stages[].stage.{input,response,output}`. Schema: `tests/schema/engine.schema.json`. | By hand. Core features need at least one test; `requires:` may only name Extended features. |
| `tests/unit/{operators,transformations}/*.json` | Unit-tier cases (SecRules Test Set shape). Strings are **byte strings**: every code point ≤ U+00FF, one byte each; adapters Latin-1 encode them. | Regenerated by `tools/import_sts.py` from the SecRules Test Set, except files in its `HAND_MAINTAINED` set; cases in `EXCLUDED_CASES` (by parameter) and `EXCLUDED_INPUTS` (by input) are dropped on import. Edit the importer sets, not just the JSON. |
| `tests/README.md` | The data contract adapters implement: tiers, byte strings, what "triggered" means, interruptions, log assertions. | By hand, together with the schemas. |
| `compat/matrix.json` → `compat/matrix.md` | Per-feature support for v2, v3 and Coraza with the spec status. | Edit the JSON, then run `uv run python tools/matrix.py`. Never edit `matrix.md` by hand; the validator fails if it is stale. |
| `compat/known-gaps.md` | Core tests each engine fails today: one row per test file with the engine, the behaviour and the spec anchor or ADR deciding it, plus a prose list of divergences no test can observe. | By hand. Rows naming Coraza or libmodsecurity v3 are the adapters' expected-failure list and are verified in CI: an unlisted failing file fails the build, and a listed file that passes fails with "known-gaps row is obsolete". Rows naming only ModSecurity v2 are predictions. |
| `adapters/coraza/` | Go reference adapter (Coraza v3.8.1 pinned in `go.mod`). | `cd adapters/coraza && go test ./...` |
| `adapters/libmodsecurity/` | Python/ctypes reference adapter over the libmodsecurity v3 C API. Needs `MODSECURITY_LIB` pointing at a `libmodsecurity.so`/`.dylib` built with libxml2, yajl and PCRE2 (recipe in its README; CI builds v3.0.16 from source and caches it). Reads matched rules from the engine debug log because the C API omits `nolog` matches. | `MODSECURITY_LIB=… uv run python -m unittest discover -s adapters/libmodsecurity` |
| `tools/` | `validate.py` (all invariants, CI runs it), `matrix.py`, `import_sts.py`, `engine_rules.py` (engine profiles to JSON for the Lean parser), and their unit tests `test_*.py`. | `uv run python tools/validate.py`; `uv run python -m unittest discover -s tools -t .` |
| `formal/` | Lean 4 model (`lakefile.toml`, no dependencies beyond the toolchain). `SecLang/Transformations.lean` defines every transformation of spec 07 and `SecLang/Operators.lean` every library-free operator of spec 06 over `ByteArray`; `SecLang/Syntax.lean` parses configuration text per spec 01, 02 and 04 with the vocabulary of 05–08 in `SecLang/Names.lean`; `SecLang/Semantics.lean` is the processing model of spec 03 over the AST (regex oracle in `SecLang/Regex.lean`, store with URL-encoded, multipart and JSON bodies and the body limits in `SecLang/Request.lean`) with theorems for ADR-0016, ADR-0017 and the body-limit interruption; everything carries `#guard` checks. `lake exe seclang-check` runs `tests/unit/transformations` (and, given the directory, `tests/unit/operators`) against the definitions, `lake exe seclang-parse` checks every engine profile's `rules` against `expect_error`, and `lake exe seclang-eval` runs every supported profile's stages through the semantics (input for both from `tools/engine_rules.py`); all exit non-zero on any mismatch. The model is a reference, not an engine: no known-gaps rows; a mismatch is a corpus, profile, spec or model defect to fix before merge. | `cd formal && lake build && lake exe seclang-check && lake exe seclang-parse .lake/engine-rules.json && lake exe seclang-eval .lake/engine-rules.json` (needs elan; see `formal/README.md`) |
| `site/` | Hugo site (Hextra theme as a Hugo module). Content adapters render `spec/`, `compat/` and `adr/` in place: nothing in `site/content` duplicates a source file; backticked references and `ADR-NNNN` mentions become links. | `hugo -s site --gc --minify --cleanDestinationDir && site/smoke.sh` |
| `docs/superpowers/` | Design documents and implementation plans the work was built from. Historical; not published. | Add a new pair for new subsystems. |
| `.github/workflows/` | `validate.yml` (validator + tools tests, Coraza adapter, libmodsecurity adapter, Lean model), `pages.yml` (site build on PRs, deploy to GitHub Pages on `main`). | Keep third-party actions pinned to a commit SHA. |

Published site: <https://fzipi.github.io/seclang-spec/>. Spec design: `docs/superpowers/specs/2026-10-06-seclang-spec-design.md`.

## Conventions you must keep

- **Status labels** (`spec/00-conventions.md`): Core MUST be implemented and is all-or-nothing for conformance; Extended SHOULD be and is declared per engine through `requires:`; Deprecated MUST parse and MAY be ignored; Engine-specific is reserved. Core started as the intersection of the three engines restricted to what OWASP CRS v4 and the recommended configurations use.
- **Anchors** are GitHub heading slugs: lower-case, keep letters, digits, `_`, spaces and hyphens, spaces to hyphens. `ctl:` options are headed `### ctl:name` and referenced as `08-actions.md#ctlname`. Tests and ADRs point at the spec with `file.md#anchor`; the validator rejects dangling anchors.
- **Cross-references** in prose are written as backticked paths: `` `06-operators.md#rx` ``, `` `tests/engine/actions/setvar.yaml` ``, plain `ADR-0024`. The site turns these into links; markdown links are used only in `adr/README.md`. A Coraza ADR is always written with the word directly before the number, `Coraza ADR-0015` (never "its ADR-0015" or "ADR-0015 and ADR-0016"), so it links to `corazawaf/coraza/docs/adr` instead of a local ADR; the validator rejects a bare `ADR-NNNN` that has no local file.
- **"Triggered"** means the rule matched, whether or not it logs; `allow` is not an interruption; body-limit interruptions carry `rule_id: 0`.
- **Engine facts need a source pointer**: file and symbol in the engine's repository, with the version surveyed (v2 `v2/master` 2026-09, libmodsecurity v3.0.16, Coraza v3.8.1). Prefer running an adapter over reading source; the adapters have corrected the spec several times.
- **When an adapter run disagrees with the spec**, classify before editing: engine divergence → known-gaps row with a source pointer; spec or test defect → fix the spec/test and rerun both adapters; adapter defect → fix the adapter with a failing test first. A corpus case the spec rejects goes into the importer's `EXCLUDED_CASES` with a comment.
- **Python always through `uv`**: `uv sync`, `uv run …`, dependency groups in `pyproject.toml`. No `pip`, no hand-made virtualenvs.

## Before you commit

```sh
uv sync
uv run python tools/validate.py                      # 0 error(s)
uv run python -m unittest discover -s tools -t .     # importer, matrix, validator tests
(cd adapters/coraza && go test ./... -count=1)       # when tests/, compat/ or the adapter changed
MODSECURITY_LIB=… uv run python -m unittest discover -s adapters/libmodsecurity   # same, if the library is available
hugo -s site --gc --minify --cleanDestinationDir && site/smoke.sh                 # when site/ or any published markdown changed
(cd formal && lake build && lake exe seclang-check && lake exe seclang-check ../tests/unit/operators)   # when formal/, spec/06-07 or tests/unit changed
uv run python tools/engine_rules.py > formal/.lake/engine-rules.json && (cd formal && lake exe seclang-parse .lake/engine-rules.json && lake exe seclang-eval .lake/engine-rules.json)   # when formal/, spec/01-09 or tests/engine changed
```

CI runs the first four and the Lean check on every push and pull request and builds the
site; a pull request cannot deploy it.
